1. Fundamente

Ce este un prompt

Promptul este instrucțiunea pe care o dai modelului. Același model, prompturi diferite → rezultate diferite.

Vag

„Scrie despre Paris." → răspuns generic, imprevizibil.

Bun

„Scrie 3 propoziții despre Paris pentru un elev de clasa a 5-a, în română." → util și controlat.

Prompt engineering = arta de a fi explicit: ce vrei, pentru cine, în ce formă.
Prompt Engineering3 / 16
Ideea-cheie: controlul vine din specificitate. Un prompt bun reduce ambiguitatea.
1. Fundamente

Mesaje cu roluri

O conversație este o listă de mesaje, fiecare cu un rol:

system

Instrucțiunile generale: cine e modelul și cum răspunde.

user

Întrebarea sau cererea concretă.

assistant

Răspunsul modelului, păstrat în istoric.

tool

Rezultatul unei unelte (la agenți).

Promptul „de sistem" e locul unde pui regulile stabile ale conversației.

Prompt Engineering4 / 16
system = reguli; user = cerere; assistant = răspuns. Modelul nu ține minte singur — istoricul se retrimite.
2. Framework

Anatomia unui prompt bun

Context

Fundalul relevant de care are nevoie modelul.

Sarcină clară

Ce anume vrei, cu un verb concret.

Format dorit

Listă, tabel, JSON, număr de cuvinte.

Exemple

Arată o mostră de intrare → ieșire.

Ton & audiență

Pentru cine și în ce stil.

Constrângeri

Ce să NU facă; limite de lungime, surse.

Prompt Engineering5 / 16
Aceste ingrediente se regăsesc, structurate, în framework-ul CROFC de pe slide-ul următor.

2. Framework

Vag vs. structurat

Vag

„Scrie-mi o ofertă pentru un client."

CROFC

Context + Rol + Obiectiv + Format + Constrângeri → răspuns gata de folosit.

C — Context      Pregătesc o ofertă pentru un client nou, fără experiență tehnică.
R — Rol          Acționează ca un consultant de business.
O — Obiectiv     Scrie oferta pe baza serviciilor mele.
F — Format       Răspunde în 5 puncte clare.
C — Constrângeri Maximum 120 de cuvinte, ton profesionist, fără jargon.
Prompt Engineering7 / 16
Același obiectiv, dar structura face rezultatul predictibil și reutilizabil (șablon).
3. Tehnici

Zero-shot vs. few-shot

La few-shot dai câteva exemple de intrare → ieșire. Modelul imită tiparul.

Clasifică sentimentul (pozitiv / negativ):

Text: „Livrare rapidă, sunt încântat!"   -> pozitiv
Text: „Produsul s-a stricat în 2 zile."   -> negativ
Text: „Ambalaj frumos, dar scump."        ->

2–5 exemple sunt de obicei suficiente. Exemplele arată formatul exact al răspunsului.

Prompt Engineering8 / 16
Zero-shot = fără exemple. Few-shot = cu exemple. Exemplele fixează atât sarcina, cât și forma ieșirii.
3. Tehnici

Gândește pas cu pas

La probleme cu raționament, cere modelului să explice pașii înainte de răspuns (chain-of-thought).

Fără

„Cât fac 17 × 24?" → răspuns direct, uneori greșit.

Cu

„Rezolvă pas cu pas, apoi dă rezultatul." → mai fiabil la calcul și logică.

Util pentru matematică, logică, decizii. Dezavantaj: răspuns mai lung și mai lent.
Prompt Engineering9 / 16
„Let's think step by step" îmbunătățește raționamentul. Pentru răspuns final curat, cere la final doar rezultatul.
3. Tehnici

Format și constrângeri

Cere forma

„Răspunde doar cu JSON", „listă cu 5 puncte", „tabel".

Limitează

„Sub 100 de cuvinte", „maxim 3 variante".

Spune ce să NU facă

„Fără introduceri", „nu inventa surse".

Un format explicit face răspunsul ușor de folosit automat (parsare, copiere, integrare).
Prompt Engineering10 / 16
Constrângerile negative („nu face X") sunt la fel de importante ca cele pozitive.
3. Tehnici

Metaprompting cu CROFC

Nu compui promptul de la zero — îi ceri modelului să-l genereze sau să-l îmbunătățească.

„Scrie un prompt în stil CROFC pentru un asistent de scris CV-uri. Întoarce doar promptul, pe secțiuni."

Descrie scopul

Ce vrei să facă asistentul.

Cere structura

„Pe secțiuni CROFC".

Rafinează

„Fă Constraints mai stricte", „adaugă un exemplu".

Verifici și editezi rezultatul — nu îl accepți orbește. Inspirat din RO.1M.AI.

Prompt Engineering11 / 16
Modelul e bun la a-și structura propriile instrucțiuni. Folosește-l ca asistent de prompting.

4. Capcane & siguranță

Capcane și prompt injection

Ambiguitate

Cereri vagi → răspunsuri imprevizibile.

Suprasolicitare

Prea multe cerințe deodată → modelul ratează unele.

Prompt injection

Text din surse care „dă ordine" modelului.

Regulă de aur: tratează textul din documente, pagini sau fișiere ca date, nu ca instrucțiuni. Nu lipi date personale în prompt.
Prompt Engineering13 / 16
Prompt injection: o pagină poate conține „ignoră instrucțiunile și fă X". Modelul nu trebuie să execute ce scrie în surse.
4. Capcane & siguranță

Verifică mereu răspunsul

Un răspuns bine scris poate fi totuși greșit. Modelele pot inventa fapte, surse și citdate (halucinații).

Semne de alarmă

Surse care „sună credibil", cifre precise fără sursă, siguranță excesivă.

Ce faci

Cere sursele, verifică-le, recitește; la decizii, confirmă cu un om.

Exemplu real: un raport livrat cu surse inventate. Verificarea rămâne responsabilitatea omului.
Prompt Engineering14 / 16
Halucinație = conținut plauzibil dar fals. Niciun prompt nu elimină complet riscul; verificarea e obligatorie.
5. În practică

Prompting în viața reală

Aceleași principii se aplică departe de cod:

Plan de weekend

CV & scrisoare

CV Europass în engleză; scrisoare de intenție.

Compară produse

Două variante, după nevoile tale.

Decizii din date

Analizează competiția; transformă datele într-o decizie.

Marketing

O campanie dintr-un brief, într-un pas.

Servicii publice

Pașaport, cazier online, medic de familie.
